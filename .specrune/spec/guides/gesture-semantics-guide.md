# 手势语义需求先列状态矩阵（gesture-semantics）

来源：2026-10-26 指令面板"下拖关闭"需求连绕三圈——size class 判断失败
（Duo 的 size class 双向不可靠，见 req:ios/duo-layout.md）→ 宽度阈值
被否 → 最终发现需求本身就是"按键盘状态分派"。前两圈各烧掉一轮真机
构建+装机（约 8 分钟/轮），都在回答一个错误的问题。

## 触发场景

- 需求说"某个手势/操作 = 某个效果"（"下拖就是关闭"、"点这里展开"）
- 效果描述里的动词隐含上下文（"关闭"——关什么？）

## 检查清单

1. 先列状态矩阵再写代码：该手势可能发生的状态组合 × 每种组合下期望
   的效果。指令面板的例子：

   | 状态 | 下拖效果 |
   |---|---|
   | 键盘开 | 收键盘，面板保留 |
   | 键盘关（⌘ 强制展开） | 关面板 |
   | 键盘关（斜杠匹配展开） | 关面板 |

   矩阵列不满 = 需求有歧义，问用户，别猜。
2. 优先找状态语义而非形态分类。"键盘是否展开"是现成状态
   （`draft.isFocused`）；"哪块屏幕/宽窄"要先造判断且 Duo 上
   size class 不可靠。
3. 状态分派写成早退分支，别嵌套形态判断——每个分支一个动作，
   与既有按钮行为保持同一语义（下拖=关闭按钮）。
