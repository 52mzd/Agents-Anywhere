# Design — Duo 半折笔记本模式

## 现状与前置

iOS 27.1 SDK 无公开折叠 API（全符号零命中），半折感知只能靠窗口几何。**实施第一步是 R0 探测实验**，其结论决定 R3 自动触发是否可靠。

## 结构

```text
ChatShellView
 └─ compact 分支
     └─ CompactChatShellView（现状：两 Tab）
         └─ 新增 laptop 模式容器（进入会话详情时可用）
             ├─ 上区（约 55% 高）：TimelineView 复用（可滚动 + 回底按钮）
             ├─ 折痕分隔（视觉线 + 卡片不跨界的布局边界）
             └─ 下区（约 45% 高）：Reactive Deck
                 ├─ 输入框常驻主位（复用现有输入组件）
                 ├─ 审批卡覆盖层（有 pending 时弹出，可划走）
                 └─ 底排快捷：打断 / 继续 / 更多
```

## 关键决策

1. **挂在会话详情层而非根壳层**：半折模式是「看某个会话」的姿态，不是全局导航形态；合盖两 Tab / 展开双栏 / 半折笔记本是三个正交形态，后者只在 SessionChatView 场景生效，避免重做根路由。
2. **Reactive Deck 输入优先**（用户定）：输入框常驻；审批卡为覆盖层（`sheet` 风格自下弹出，可下滑收起），不抢占输入焦点。
3. **折痕对齐**：上下区按窗口几何比例分割（探测后修正），卡片列表布局约束在折痕上方截止。
4. **R0 探测结论（2026-10-23 实测）→ 纯手动触发**：Duo 模拟器半折态 framebuffer/safe area/布局与展开态完全一致（内容分布贯穿全屏），系统不给 app 任何半折信号。自动几何检测不可行；实现为菜单「笔记本模式」开关（`@AppStorage`），开启后按 50% 屏高（物理折痕位置）画上下分区与折痕分隔线。
5. **状态无缝**：继续依赖 Repositories 层与共享 `chatSelection`（上任务已验证的模式）。

## 数据流与契约

无新 API、无持久化；laptop 开关为 `@AppStorage` 布局偏好（进程外记忆）。

## 备选方案

- **把 laptop 做成根级第三形态（重做路由）**：把三形态并列在 ChatShellView 分流——拒绝：半折是会话内姿态而非导航形态，根级改动大且影响已定型的两 Tab。
- **下屏用原生键盘区（不画自定义面板）**：依赖系统在半折时自动弹键盘于下半屏——不可控且无审批/快捷操作位，拒绝。
- **等苹果公开 posture API 再做**：交付无限期推迟；几何启发式 + 手动开关在任何未来 API 下都不作废，拒绝。

## 兼容与回滚

- 非 Duo / 非半折几何下启发式不触发，普通 iPhone 零影响。
- 回滚点：laptop 容器为新增独立文件，删除即回滚；根壳与会话详情仅加挂载点。
